# B4-1 보너스 과제

## 보너스 1. 통계 리포트

`agent-admin` 로그인 셸에서 [report.sh](report.sh)를 실행해 현재 로그 전체 또는 양 끝을 포함한 시간 구간을 집계한다. 입력은 현재 `monitor.log` 한 파일이며, 최댓값이나 최솟값이 같은 표본이 여러 개면 처음 나온 시각을 표시한다.

```sh
"$AGENT_HOME/bin/report.sh"
"$AGENT_HOME/bin/report.sh" '2026-11-19 03:14:00' '2026-11-19 03:15:59'
```

코드를 읽을 때는 마지막 두 호출부터 본다. `check_range`는 입력한 시각을 검사하고, `print_statistics`는 범위에 들어오는 줄만 세면서 합계와 최댓값·최솟값을 구한다. 평균은 마지막에 합계를 샘플 수로 나눈다.

자동 점검에서는 샘플 3개 중 시간 범위에 들어가는 2개만 집계했다. CPU 10%·20%의 평균은 15%, MEM 5%·3%의 평균은 4%, DISK 30%·40%의 평균은 35%였다. 각 자원의 최댓값·최솟값과 해당 시각, 빈 구간의 샘플 수 0도 대조했다.

## 보너스 2. 시간 기반 로그 보존

`agent-admin`의 cron이 매일 00:15(KST)에 [archive-logs.sh](archive-logs.sh)를 실행하도록 등록했다. 최종 수정 후 7일이 지난 `/var/log/agent-app/*.log`를 gzip으로 압축해 `/var/log/monitor/agent-app/archive/`에 저장한다. 압축본 자체의 최종 수정 시각으로부터 30일 이상 지나면 다음 실행에서 삭제한다. 스크립트가 만든 압축본에는 압축 당시 시각이 기록된다. 숫자 백업(`monitor.log.1`~`.9`)은 필수 스크립트의 용량 교체 대상이다.

`main`에서 `check_directories`가 읽고 쓸 디렉토리를 확인한다. `archive_old_logs`는 날짜로 후보를 고르고, `log_is_open`으로 사용 중인지 확인한 뒤 `compress_log`에 한 파일씩 넘긴다. 마지막 `find`가 보관 기한이 지난 압축본을 삭제한다.

임시 디렉토리에서 6일 된 로그와 7일 된 로그, 29일 된 압축본과 30일 된 압축본을 함께 시험했다. 7일 된 닫힌 로그만 압축됐고 압축을 풀어 원문이 같은지 확인했다. 29일 된 압축본은 남고 30일 된 압축본은 삭제됐다. 같은 작업을 다시 실행해도 압축본은 1개였다. 실행 계정이 `/proc`에서 열린 파일로 확인한 로그는 그 회차에 건너뛴다. 아카이브 디렉토리가 없거나 쓸 수 없으면 경고 후 종료한다.

검증은 Mac의 저장소 루트에서 `./scripts/verify-b4-1.sh`를 실행한다. 출력의 `[선택 과제]`에서 일일 cron 등록, 운영 로그 리포트 실행, 통계 표본과 보존 기한 시험을 확인할 수 있다. 이 네 항목이 모두 통과했다.
