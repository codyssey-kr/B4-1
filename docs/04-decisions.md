# 판단 필요 사항

실습에 적용한 설정과 제출 전에 확인할 사항을 기록했다.

## A. 제출 전에 확인할 사항

### A1. 로그인 환경과 제공 앱의 키 경로

로그인 셸의 `AGENT_KEY_PATH`는 미션에 명시된 `$AGENT_HOME/api_keys/t_secret.key`다. 제공 앱은 디렉토리를 요구하므로 기동 명령에서만 파일명 접미사를 제거한다. 앱이 여는 `secret.key`는 같은 디렉토리의 `t_secret.key`를 가리킨다. [수행 내역서 3.8](../required/B4-1-수행내역서.md#38-미션-문서와-다르게-적용한-사항)에 두 이름을 사용한 이유를 기록했다.

### A2. 실습 환경이 컨테이너다

- **현재 적용**: OrbStack의 Ubuntu 22.04 arm64 컨테이너. 문서의 "Ubuntu 22.04 LTS 또는 동등 리눅스 환경"과 "컨테이너/VM"에 근거했다.
- **판단**: 평가에서 VM이나 systemd 기반 확인을 요구하면 환경을 다시 구성해야 한다. 설정 명령은 내역서 3장에 있다.

### A3. 제출 형식

- **현재 적용**: 내역서는 Markdown이고 증거는 명령 출력 텍스트다.
- **판단**: 제출처가 PDF나 터미널 스크린샷을 요구하면 변환하거나 [평가 대비](03-evaluation-guide.md)의 명령으로 캡처한다.

### A4. 제출 범위와 공개 여부

- 필수 제출물 두 개는 저장소의 `required/`에 있고, 선택 과제의 코드와 검증 결과는 `bonus/`에 있다.
- **판단**: 공개로 전환할지 정한다. 키 값 `agent_api_key_test`는 미션 문서에 공개된 시험용 값이다. E절에는 개인 장비 이름과 SSH 키 이름이 있으므로 공개 전에 삭제한다.

## B. 선택 과제

통계는 `report.sh`를 실행할 때 출력한다. 시작·종료 시각을 생략하면 현재 `monitor.log` 전체를 집계한다. 오래된 로그는 `agent-admin`의 cron이 매일 00:15에 처리한다. 압축과 만료 기준은 [보너스 과제](../bonus/README.md)에 기록했다.

## C. 구현 방식 선택

| ID | 항목 | 현재 적용 | 다른 선택지 | 바꿀 이유 |
|---|---|---|---|---|
| C1 | 방화벽 | UFW | firewalld | Ubuntu 기본 도구라 유지를 권장 |
| C2 | 로그 교체 | 스크립트 구현 | logrotate | 표준 도구 사용을 요구받을 때 |
| C3 | 방화벽 상태 조회 | `ufw status`만 sudo 허용 | `/etc/ufw/ufw.conf` 확인 | sudo 설정을 없애고 싶을 때. 다만 실제 활성 상태와 다를 수 있다. |
| C4 | 로그의 PID | 이름이 일치하는 비좀비 중 가장 큰 PID(실습에서는 자식) | 부모 프로세스 | 부모 PID 기록을 요구받을 때 |
| C5 | 앱 실행 | `nohup` 백그라운드 | systemd 서비스 | VM으로 옮길 때 자동 재시작이 필요하면 |
| C6 | 보존 대상 | 로그 디렉토리의 `*.log` | `app.out` 별도 관리 | 앱 표준 출력 파일까지 보존할 때 |

## D. 평가 시 알아둘 제한

- **SSH 비밀번호 없음**: 실습 계정에는 비밀번호를 설정하지 않았다. 일반 계정 SSH 로그인을 시연하려면 공개키를 등록해야 한다. 자격 증명 없이 접속에 실패한 결과만으로는 차단 원인을 구분하기 어렵다. 수행 내역서 4.1에 같은 공개키로 일반 계정은 성공하고 root는 거부된 결과를 기록했다.
- **Mac 잠자기**: 잠자기 중에는 cron이 멈춰 로그 간격이 벌어진다. Mac에서 `caffeinate -i ./scripts/verify-b4-1.sh`를 실행하면 점검 중 유휴 시스템 잠자기를 방지한다.
- **재시작 후 복구**: Mac이나 컨테이너를 재시작하면 앱과 UFW가 꺼진다. `./scripts/start-b4-1.sh`로 복구한다.
- **CPU 경고**: 18코어 전체 기준이라 평상시 20%를 넘는 일이 드물다. [평가 대비](03-evaluation-guide.md)의 부하 시연을 사용한다.
- **포트 장애 시험**: 포트만 닫힌 상태는 앱을 수정하지 않고 만들 수 없어, 사용하지 않는 포트를 점검 대상으로 지정해 재현했다.

## E. 정리가 필요한 부수 작업

과제 진행 중 만들었지만 최종 환경에는 쓰지 않는 항목이다. 삭제는 되돌릴 수 없어 그대로 두었다.

| 항목 | 위치 | 정리 방법 |
|---|---|---|
| WSL 배포판 `wsl-b4-1` | evo | evo에서 `wsl --unregister wsl-b4-1` 실행 |
| Mac의 SSH 공개키 `M5` | evo의 `authorized_keys`, `administrators_authorized_keys` | 원격 접속이 더 필요 없으면 `M5`로 끝나는 줄 삭제 |
| Mac의 SSH 공개키 `id_ed25519` | evo의 `authorized_keys` 또는 `administrators_authorized_keys` | 이번 과제 전부터 쓰던 키일 수 있으므로 용도를 확인한 뒤 삭제 |
| 컨테이너 `b4-1` | OrbStack | 평가 종료 후 `docker --context orbstack rm -f b4-1` 실행 |
